# Why there is no front end

Klopotek is a database with a subscription. The records underneath it are ordinary: titles, contracts, rates, advances, sales, statements. What you pay for is the layer on top that lets people who do not write SQL get at them: screens, filters, forms, the statement run button.

That layer used to be the whole product, because talking to a database was hard. It is not hard any more. Open this folder in Claude Code, describe what you want, and it runs the right command and explains the answer. Ask a question the screens never had a report for and you still get an answer.

## What you gain

- **Better answers.** Ask which overseas authors are being withheld at the default rate, or which titles crossed an escalator this period, in your own words.
- **No seats.** Your rights manager, your finance person and your publisher can all look. The bill does not grow with headcount.
- **Your data in your own Postgres.** Plain tables. Back them up, query them from anything, leave any time.
- **A process that matches you.** When an agent negotiates a new clause, you add a field or a rule with `/customise`. You do not wait for a vendor release.

## What you give up

- **An author portal.** Authors get their statement as a document, not a login. Enterprise DNA builds a portal into a customised version.
- **A phone app and screens to click through.** It runs where Claude Code runs.
- **ONIX feeds out and editorial workflow.** This reads ONIX; it does not send it.
- **A vendor help desk.** This is open source. Enterprise DNA supports the installed version for publishers who want someone to call.

## Who this fits

Independent publishers with a list of a few hundred titles and a royalty run that matters more than a screen. If your team lives in a production system all day, keep it for that and run royalties here.
